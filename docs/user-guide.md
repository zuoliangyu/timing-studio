# Timing Studio 用户手册

Timing Studio 用文本描述数字信号，并在浏览器中实时生成时序图。解析和绘图由本地 WebAssembly 完成，输入内容不会上传到服务器。

## 1. 界面组成

- 顶部工具栏：切换示例、导入或下载源文件、撤销/重做、导出 PNG 或 SVG。
- 快捷积木栏：插入时钟、数字信号、总线、时间标记或区间标注。
- 左侧编辑器：通过 `积木` / `DSL` / `YAML` 切换三种编辑方式。
- 积木编辑器：直接修改图表属性、信号参数、状态点、总线片段、时间标记和区间箭头。
- 左下状态栏：显示“描述有效”或具体错误；点击错误可跳到对应行。
- 右侧“实时波形”：以论文常用的白底、黑色直角边沿和浅灰网格显示最终时序图。

## 2. 画出第一张图

1. 打开页面。
2. 点击右上角“示例”，选择“简洁 DSL”。
3. 修改左侧信号名称、时间或总线值。
4. 等待“正在校验”消失。
5. 确认左下角显示“描述有效”。

也可以直接输入：

```text
timing 1
title "Ready / Valid 握手"
unit cycle

clock CLK cycles 6
signal VALID low@0 high@2 low@8
signal READY low@0 high@4 low@10
bus DATA A5@2..5 3C@5..8
mark "第一次传输" @4
span 2..8 "握手有效窗口"
```

## 3. 常用语句

| 目的 | 写法 | 说明 |
|---|---|---|
| 设置标题 | `title "SPI 读取"` | 标题包含空格时必须使用双引号 |
| 设置单位 | `unit ns` | 默认单位是 `cycle` |
| 绘制时钟 | `clock CLK cycles 8` | 默认周期为 2，默认从 0 开始 |
| 绘制数字信号 | `signal CS high@0 low@1 high@9` | 时间必须严格递增 |
| 绘制总线 | `bus DATA A@0..4 B@4..8` | 片段必须按时间排列且不能重叠 |
| 添加分组 | `... group SPI` | `group` 必须放在行尾 |
| 添加标记 | `mark "采样" @4` | 在指定时间绘制垂直标记 |
| 添加区间标注 | `span 2..14 "固定闸门时间 T_g"` | 在波形下方绘制双向箭头 |
| 添加注释 | `# 这是注释` | 也可以写在语句末尾 |

完整语法见 [DSL v1 规范](dsl.md)，完整 SPI 示例见 [quick-start.timing](examples/quick-start.timing)。

## 4. 修改和排错

编辑后应用会等待约 120ms，再调用 Rust/WASM 校验并更新预览。校验期间旧图会变淡，导出按钮暂时禁用。

发生错误时：

1. 查看左下角错误原因。
2. 检查红色行号。
3. 点击错误信息，编辑器会选中对应行。
4. 修正后等待重新校验。

常见错误：

- `未知语句`：命令拼写错误，例如把 `clock` 写成 `clok`。
- `未知时钟参数`：参数拼写错误，例如把 `period` 写成 `peroid`。
- `时间必须严格递增`：后一个数字采样点早于或等于前一个。
- `总线片段不能重叠`：后一片段的开始时间早于前一片段的结束时间。
- `group 缺少值`：写了 `group`，但没有提供分组名称。
- `引号未闭合`：文本开头有 `"`，但缺少结尾引号。

## 5. DSL、YAML 与积木

- `积木`、`DSL` 和 `YAML` 是三个并列的编辑模式，共享同一个 Rust `Diagram`。
- 点击 `DSL` 或 `YAML` 会把当前有效内容转换成目标格式。
- 转换以同一个 Rust `Diagram` 为中间模型，波形语义保持一致。
- 转换会重新格式化文本，不保留注释、空行、字段顺序和手工排版。
- 积木模式可以编辑信号名称、分组和类型；时钟的周期、循环和开始时间；数字信号的逻辑值和变化时间；总线的数据值及起止时间。
- 信号支持拖拽排序、上移、下移、复制和删除；状态点与总线片段支持独立增删。
- 时间标记和区间箭头可以独立修改标签与时间。
- 积木修改通过 `Diagram` 回写当前文本格式，因此会重新格式化 DSL 或 YAML。
- 数值输入在按 Enter 或离开输入框时提交；不合法的修改会被 Rust 校验拒绝，并保留上一个有效波形。
- 区间标签支持 `T_g` 和 `T_{gate}` 下标语法，导出的 SVG 不依赖外部数学排版库。
- DSL 更适合人工编辑，YAML 更适合程序生成和结构化交换。

## 6. 导入和保存描述

点击顶部文件图标可以导入：

- `.timing`、`.txt`：推荐用于简洁 DSL；
- `.yaml`、`.yml`：结构化 YAML；
- `.json`：结构化 JSON。

每次校验成功后，当前描述会自动保存在这个浏览器的 `localStorage` 中，下次打开页面会自动恢复。自动保存不是跨设备备份；需要长期保存时，请将左侧文本复制到文本编辑器，并保存为 `.timing` 文件。

点击顶部下载源文件图标，会根据当前文本格式下载 `timing-diagram.timing` 或 `timing-diagram.yaml`。存在语法错误的内容不会覆盖自动保存记录。

## 7. 撤销与重做

- 顶部左弯箭头撤销最近一次修改，右弯箭头重做。
- 积木操作、DSL/YAML 转换和文本编辑共享同一份历史。
- 连续文本输入在离开编辑器时合并成一个撤销步骤。
- 最多保留最近 50 个历史快照，刷新页面后历史不会保留。

## 8. 预览控制

- “放大”和“缩小”：在 40%～200% 范围调整预览尺寸。
- 百分比按钮：恢复 100%。
- “适应窗口”：恢复适合当前面板的默认尺寸。

导出图固定使用论文友好的黑白样式，不跟随工作台配色变化。

缩放只影响屏幕预览，不改变信号时间或 SVG 几何数据。

## 9. 导出图片

- `导出 SVG`：保留矢量路径，适合文档、网页和后续编辑。
- 图片图标：导出 2 倍分辨率 PNG，适合聊天、幻灯片和普通图片查看器。

只有当前描述校验成功后才能导出。文件名默认为 `timing-diagram.svg` 或 `timing-diagram@2x.png`。

## 10. YAML/JSON 输入

程序生成数据时可以使用 YAML 或 JSON。二者与 DSL 使用同一套 Rust 数据模型和时间校验。示例：

```yaml
title: Enable sequence
unit: ns
signals:
  - name: CLK
    clock: { period: 1, cycles: 4 }
  - name: ENABLE
    digital:
      points:
        - { at: 0, value: low }
        - { at: 1.5, value: high }
```

人工编写优先使用 DSL；程序交换、已有结构化数据或需要完整字段名时使用 YAML/JSON。

## 11. 隐私和离线使用

- 渲染在浏览器本地完成，没有渲染服务端。
- GitHub Pages 只提供 HTML、CSS、JavaScript 和 WASM 静态文件。
- PWA 缓存完成后可以离线打开已访问过的版本。
- 输入文件只由当前浏览器读取。

## 12. 当前限制

当前版本不支持：

- 拖拽式时间轴编辑；
- VCD/FST 或逻辑分析仪数据导入；
- 信号之间的因果箭头、延迟关系和区间着色；
- PDF 导出；
- 云端保存、账号同步和多人协作。
